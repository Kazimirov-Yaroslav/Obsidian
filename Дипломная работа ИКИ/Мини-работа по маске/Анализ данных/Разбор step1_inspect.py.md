## 1. Словарик: термины, нужные для чтения кода

- **BSCALE/BZERO**: линейное преобразование между целым в файле и физическим значением (формула — [[Анализ данных]] §2.1); надпись `int16 (rescales to float32)` означает, что в тайлах лежит int16, а отдаётся float32.
- **RSUN_OBS / DSUN_OBS**: видимый угловой радиус Солнца (arcsec) и расстояние до него (м); меняются в году из-за эллиптичности орбиты (январь ≈ 984″, июль ≈ 959″).
- **TAI, T_REC, T_OBS**: TAI — атомная шкала времени без секунд координации; T_REC — номинальное время узла сетки 96 мин (им именуются файлы); T_OBS — фактическое время наблюдения; расходятся на минуты из-за интерполяции серии на равномерную сетку.
- **QUALITY**: битовая маска качества: каждый бит = флаг события; 512 = установлен бит №9; полную расшифровку не делали, используем эмпирические QC-правила flat/dip.
- **LOS-магнитограмма**: карта проекции магнитного поля на луч зрения (подробно — [[Анализ данных]] §2.5).
- **mu и CLV**: mu = cos θ, θ — гелиоцентрический угол между лучом зрения и локальной вертикалью; CLV (center-to-limb variation, лим-потемнение) — зависимость интенсивности от mu.
- **Перцентили p1/p50/p99**: значение, ниже которого лежит 1%/50%/99% пикселей; p50 = медиана; устойчивы к выбросам, в отличие от среднего и максимума.

## 3. Функция trec_of: разбор ключа пары

```python
def trec_of(p: Path) -> str:
    return p.name.split("_TAI.")[0].split(".", 1)[1]
```
- `p.name` — имя файла строкой: `mdi.fd_Ic_interp.20050101_000000_TAI.continuum.fits`.
- `.split("_TAI.")` — рез по каждому вхождению подстроки `_TAI.`, результат — список: `["mdi.fd_Ic_interp.20050101_000000", "continuum.fits"]`.
- `[0]` — первый элемент списка (нумерация с нуля): всё до `_TAI.`.
- `.split(".", 1)` — рез с maxsplit=1: только по первой точке, максимум два куска: `["mdi", "fd_Ic_interp.20050101_000000"]`; без единицы время отделилось бы отдельным элементом, и был бы массив из 3-х элементов.

> [!note] Когда это может повлиять.
>  Пример: float32 точно представляет целые только до 2^24 = 16 777 216, поэтому `np.float32(16777216) + np.float32(1)` снова даёт 16777216 (прибавка исчезает), а в float64 результат 16777217; для наших интенсивностей ~1.0 шаг float32 ≈ 1.2e-7, поэтому на напечатанных stats (`%.4g`) разница не видна — конверт является страховкой для последующей арифметики (нормировка, сравнения с порогами), где ошибка накапливается по миллионам пикселей.

## 6. Функция clv_profile: радиальный профиль

```python
def clv_profile(dat: np.ndarray, hdr) -> None:
    ny, nx = dat.shape
    x, y = np.meshgrid(np.arange(nx), np.arange(ny))
    r = np.hypot(x - (hdr["CRPIX1"] - 1), y - (hdr["CRPIX2"] - 1))
```
- `np.arange(nx)` — строка номеров столбцов $[0, 1, \dots, n_x-1]$; `np.arange(ny)` — строка номеров строк $[0, 1, \dots, n_y-1]$.

- `meshgrid` растягивает их в две матрицы формы (1024, 1024): в матрице `x` каждая строка равна строке номеров столбцов, то есть $x_{ij} = j$; в матрице `y` каждый столбец равен строке номеров строк, то есть $y_{ij} = i$. Смысл: у любого пикселя (i, j) обе его координаты доступны как элементы массивов, поэтому операции по всем пикселям идут без циклов Python (векторизация).

- `r` — ndarray той же формы 1024×1024, «карта радиусов» диска: каждый элемент — расстояние в пикселях от данного пикселя до центра диска:

  

$$r_{ij} = \sqrt{\left(x_{ij} - (\text{CRPIX1} - 1)\right)^2 + \left(y_{ij} - (\text{CRPIX2} - 1)\right)^2}$$

  

- `np.hypot(a, b)` вычисляет $\sqrt{a^2 + b^2}$ поэлементно; вычитание 1 из CRPIX нужно потому, что FITS нумерует пиксели с 1, а индексы numpy начинаются с 0.

- Зачем: карта радиусов позволяет дальше отбирать пиксели по радиусу (маска `disk`) и разносить их по бинам $\mu$ операциями над целыми массивами.

```python
    rsun_pix = hdr["RSUN_OBS"] / abs(hdr["CDELT1"])
    rr = r / rsun_pix
    disk = rr < 0.99
    mu = np.sqrt(np.clip(1 - rr[disk] ** 2, 0, 1))
```
- Слова «arcsec» в коде нет: это единицы значений ключей заголовка (стандарт FITS): RSUN_OBS хранится в arcsec (984.21), CDELT1 — в arcsec на пиксель (1.9856); при делении arcsec сокращаются, остаётся пиксель — размерностный разбор:

$$R_{\text{pix}} = \frac{\text{RSUN\_OBS}\ [\text{arcsec}]}{|\text{CDELT1}|\ [\text{arcsec/px}]} \approx \frac{984.21''}{1.9856''/\text{px}} \approx 495.7\ \text{px}$$

- `rr` — безразмерный радиус: $rr = r / R_{\text{pix}}$, то есть радиус в долях радиуса диска (0 — центр, 1 — лимб).
- `disk` — булева маска диска с обрезкой лимба: $rr < 0.99$ (дальше — лимбовый шум и форшортенинг).
- `mu` — косинус гелиоцентрического угла для дисковых пикселей: на проекции диска $\sin\theta = rr$, откуда

$$\mu = \cos\theta = \sqrt{1 - rr^2}$$

- `np.clip(..., 0, 1)` ограничивает выражение под корнем отрезком $[0, 1]$: на границе маски $rr \approx 0.99$ из-за округлений могло бы получиться $1 - rr^2 < 0$, и sqrt дал бы NaN и предупреждение.
- Смысл $\mu$ и CLV — [[Анализ данных]] §3.1.

```python
    I = dat.astype(np.float64)[disk]
    ok = np.isfinite(I)
    mu, I = mu[ok], I[ok]
```
- `dat.astype(np.float64)` — копия кадра в двойной точности (медианы и перцентили не теряют точность float32).
- `[disk]` в конце — булева индексация: `disk` является булевой матрицей 1024×1024 (True — пиксель внутри диска); применение такой маски собирает в одномерный массив только те элементы, где маска True. Итог `I` — интенсивности примерно $7.7\times10^5$ дисковых пикселей вместо всех 1 048 576 пикселей кадра: внедисковый космос в профиль не попадает.
- `ok = np.isfinite(I)` — вторая булева маска, уже над одномерным массивом: True там, где значение конечно (не NaN и не ±inf); NaN/±inf могут прийти из FITS как fill-значения.
- `mu, I = mu[ok], I[ok]` — синхронная фильтрация: одна и та же маска `ok` применяется к обоим массивам; так как `mu` и `I` собраны из одних и тех же пикселей в одном порядке, после фильтрации сохраняется поэлементное соответствие: `mu[k]` по-прежнему является $\mu$ именно того пикселя, чья интенсивность лежит в `I[k]`. Без синхронности пары (mu, I) перемешались бы и профиль стал бы бессмысленным.
- Зачем отбраковка: один NaN внутри бина превратил бы медиану бина в NaN (np.median propagates NaN), и в профиле появились бы дыры.

```python
    bins = np.linspace(0, 1, 41)
    idx = np.digitize(mu, bins)
    centers = 0.5 * (bins[1:] + bins[:-1])
    med = [float(np.median(I[idx == j])) if np.any(idx == j) else np.nan
           for j in range(1, len(bins))]
```
- Бин («ящик», интервал) — отрезок значений, по которым сортируют выборку, чтобы построить распределение или профиль. Здесь весь диапазон $\mu \in [0, 1]$ разрезан на 40 равных интервалов; `linspace(0, 1, 41)` возвращает 41 границу: $[0,\ 0.025,\ 0.05,\ \dots,\ 1]$.
- Зачем: вместо $\sim 7.7\times10^5$ отдельных пар (mu, I) получить компактную зависимость $I(\mu)$ — 40 точек профиля, по одной на интервал.
- `digitize(mu, bins)` — для каждого значения mu возвращает номер бина, в который оно попало (целые 1…40; бин j — это полуинтервал $[\text{bins}[j-1],\ \text{bins}[j])$); результат `idx` — массив номеров бинов той же длины, что `mu`.
- `centers` — «икс-координаты» точек профиля: середины интервалов через срезы: `bins[1:]` — все границы кроме первой (правые концы бинов), `bins[:-1]` — все кроме последней (левые концы); их полусумма даёт центры: $c_j = (\text{bins}[j] + \text{bins}[j-1]) / 2$.
- List comprehension: для каждого бина j строится булева маска `idx == j` — «какие пиксели попали в этот бин»; если бин непуст (`np.any`), в `med` кладётся медиана интенсивностей этих пикселей, иначе NaN.
- Почему медиана, а не среднее: пятна занимают ≤0.5% пикселей диска и не сдвигают медиану, но сдвинули бы среднее; медиана даёт яркость тихого Солнца в каждом бине.
- Пустые бины: маска `disk` отрезала $rr < 0.99$, то есть $\mu < \sqrt{1 - 0.99^2} \approx 0.14$, поэтому ближайшие к лимбу бины не содержат пикселей и дают NaN — это видно в печати и на графике.

```python
    for c, v in zip(centers[::4], med[::4]):
        print(f"     mu={c:.2f}  I={v:.4g}")
```
- Срез `[::4]` — взять элементы с шагом 4 (каждый четвёртый): из 40 точек профиля печатаются 10 — компактный эскиз, достаточный для взгляда в консоли; число 4 физического смысла не имеет, это утилитарный выбор «40 бинов / 4 = 10 строк», чтобы не засорять вывод.
- Ничего не теряется: график `step1_clv.png` строится по полным массивам `centers` и `med` (все 40 точек); шаг влияет только на print.
- `zip(a, b)` — параллельный обход двух последовательностей парами: (центр бина, медиана в бине); формат `:.2f` — 2 знака после точки, `:.4g` — 4 значащие цифры.

Твой вывод:
```
   CLV (mu -> медиана I):
     mu=0.21  I=1.001
     mu=0.51  I=1.001
     mu=0.91  I=1
```
Контрастный пример (продукт без CLV-коррекции, с настоящим лим-потемнением):
```
   CLV (mu -> медиана I):
     mu=0.21  I=0.412
     mu=0.51  I=0.868
     mu=0.91  I=0.993
```
Во втором случае профиль монотонно растёт к центру диска — именно так выглядел бы «физический» CLV; твой плоский профиль и есть доказательство CLV-коррекции продукта ([[Анализ данных]] §3.2).

## 7. Функция pair_sync: полнота пар

```python
    tc = {trec_of(p) for p in cont}
    td = {trec_of(p) for p in mag}
```
Set comprehension (фигурные скобки): **множество** меток времени `.continuum` и `.data`; множество хранит только уникальные элементы и умеет разности — именно то, что нужно для поиска «сирот».

```python
    print(f"   только continuum: {len(tc - td)}, только data: {len(td - tc)}")
    orph = sorted(tc - td)[:5] + sorted(td - tc)[:5]
    if orph:
        print("   примеры сирот:", orph)
```
`tc - td` — разность множеств («есть `.continuum`, нет `.data`»); `len` — количество; `sorted(...)[:5]` — первые пять примеров; `+` склеивает два списка; `if orph:` печатает примеры только при непустом списке.

Твой вывод:
```
PAIR SYNC по всей папке:
   continuum: 5139, data: 5139
   только continuum: 0, только data: 0
```
Контрастный пример (два файла потеряны при экспорте):
```
PAIR SYNC по всей папке:
   continuum: 5139, data: 5137
   только continuum: 2, только data: 0
   примеры сирот: ['20050614_160000', '20050615_080000']
```
В твоём случае разности пусты → supervised-пары полны ([[Анализ данных]] §2.4).
