## 1. Словарик: термины, нужные для чтения кода

- **`np.mgrid`** — объект-индексатор numpy, строящий сетку координат по срезу: `np.mgrid[0:ny, 0:nx]` возвращает кортеж из двух массивов формы (ny, nx): первый — «матрица номеров строк» (y), второй — «матрица номеров столбцов» (x). Это аналог `np.meshgrid` из [[Разбор step1_inspect.py]] §6, но с другим порядком присваивания (см. §4 ниже) — источник частых багов, разбираем отдельно.
- **Modulo `%`** — остаток от деления: `i % 500 == 0` истинно ровно на кратных 500 итерациях; здесь используется как дешёвый прогресс-бар.
- **Вложенные пороги** — ситуация, когда один порог строже другого и его множество целиком лежит внутри множества более мягкого порога: здесь $T_{\mathrm{UMBRA}} < T_{\mathrm{SPOT}}$, поэтому $\{\text{umbra}\} \subset \{\text{spot}\}$, и разность площадей даёт пенумбру (см. §5).
- **Булева арифметика numpy** — `&` (И), `|` (ИЛИ), `~` (НЕ) поэлементно над массивами True/False; приоритет `&` выше, чем у сравнений `<`, поэтому скобки в `(dat < T) & disk` обязательны (см. §4).
- **`csv.DictWriter`** — писатель csv, принимающий словари строк и сам расставляющий колонки по `fieldnames`.
- **`matplotlib` backend `Agg`** — неинтерактивный режим: рисуем в файл без окна (см. [[Разбор step1_inspect.py]] §6); здесь он нужен, потому что скрипт долгий и окно на 15 минут мешало бы.

## 3. `parse_date`: дата из имени файла

```python
def parse_date(p: Path) -> datetime:
    stamp = p.name.split(".")[2]
    return datetime.strptime(stamp.split("_")[0], "%Y%m%d")
```
- `p.name` — имя файла: `mdi.fd_Ic_interp.20050101_000000_TAI.continuum.fits`.
- `.split(".")` — рез по точкам: `['mdi', 'fd_Ic_interp', '20050101_000000_TAI', 'continuum', 'fits']`.
- `[2]` — третий элемент (нумерация с нуля): `'20050101_000000_TAI'`; позиция 2 фиксирована схемой имени `серия.подсерия.ДАТА_ВРЕМЯ_ШКАЛА.сегмент.fits`, поэтому дата всегда на третьем месте.
- `.split("_")[0]` — рез по подчёркиваниям, первый кусок: `'20050101'`.
- `strptime(..., "%Y%m%d")` — парсинг по формату: `%Y` = 4-значный год, `%m` = месяц с ведущим нулём, `%d` = день; возвращает `datetime`.

Твой вывод (для первого файла): `parse_date` от `mdi.fd_Ic_interp.20050101_000000_TAI.continuum.fits` → `datetime(2005, 1, 1)`, в csv попадает строка `date=2005-01-01, month=1`.

Контрастный пример (сломанная схема имени): файл `mdi.20050101.continuum.fits` (без подсерии) даёт `split(".")[2] == 'continuum'`, и `strptime('continuum', '%Y%m%d')` бросает `ValueError: time data 'continuum' does not match format '%Y%m%d'` — скрипт падает на первом же кадре. Это цена жёсткой позиции `[2]`: схема имени гарантирована JSOC-экспортом, но правило хрупкое; в `trec_of` из [[Разбор step1_inspect.py]] §3 позиция вычислялась устойчивее (через `_TAI.`).

## 4. Основной цикл: чтение кадра и маска диска

```python
conts = sorted(DATA.glob("*_TAI.continuum.fits"))
```
В отличие от step1 (там было `*_TAI.continuum*` со звёздочкой на конце), здесь расширение `.fits` указано явно: шаблон строже и не поймает hypothetical-файлы без расширения; для данной папки оба варианта дают тот же список из 5139 файлов, но явное `.fits` самодокументирует ожидание.

```python
if i % 500 == 0:
    print(f"  обработано {i}/{len(conts)}")
```
Прогресс каждые 500 кадров: `i % 500` — остаток от деления номера итерации на 500, равен нулю ровно на 0, 500, 1000, …; печать `0/5139, 500/5139, …`.

Твой вывод:
```
Анализ 5139 кадров...
  обработано 0/5139
  обработано 500/5139
  ...
  обработано 5000/5139
```
Контрастный пример (маленькая папка, 120 кадров): напечатается только `обработано 0/120`, промежуточных строк не будет — прогресс-бар «пролётит» молча, что нормально для короткого прогона.

```python
with fits.open(p) as hdul:
    dat = hdul[1].data.astype(np.float32)
    hdr = hdul[1].header
```
- `with` — гарантированное закрытие файла на каждой из 5139 итераций (иначе — утечка хэндлов ОС, [[Разбор step1_inspect.py]] §5, п. 3).
- `hdul[1]` — здесь индекс 1 захардкожен осознанно: формат interp-серии известен из step1 (COMPRESSED_IMAGE всегда второй HDU), и в отличие от step1, где мы искали первый HDU с данными универсально, здесь экономим на повторяющемся вызове `next(...)` внутри большого цикла. Это допустимый компромисс «универсальность против скорости» при гарантированном входном формате.
- `.astype(np.float32)` — в отличие от step1 (там float64 ради перцентилей), здесь float32: данные нужны только для сравнений `<` и подсчёта `.sum()`, точность ~7 знаков избыточна, а float32 вдвое экономнее по RAM и быстрее при 5139 кадрах.

```python
ny, nx = dat.shape
y, x = np.mgrid[0:ny, 0:nx]
r = np.hypot(x - (hdr["CRPIX1"] - 1), y - (hdr["CRPIX2"] - 1))
```
- `dat.shape` — кортеж (1024, 1024); распаковка `ny, nx = ...` кладёт число строк в `ny`, столбцов в `nx`.
- `np.mgrid[0:ny, 0:nx]` возвращает кортеж (массив строк, массив столбцов), поэтому присваивание идёт как `y, x = ...` — **порядок обратный meshgrid из step1**: там было `x, y = np.meshgrid(np.arange(nx), np.arange(ny))`. Оба дают одинаковые матрицы, но путаница в порядке — классический баг, поэтому запоминаем правило: `mgrid[строки, столбцы]` → первый выход = y, второй = x.
- Согласование с FITS: ось 1 (CDELT1, CRPIX1) — это столбцы = `x`; ось 2 (CDELT2, CRPIX2) — строки = `y`; в формуле `r` именно так и сопоставлено, поэтому корректно.
- Карта радиусов (та же формула, что в [[Разбор step1_inspect.py]] §6):

$$r_{ij} = \sqrt{\bigl(x_{ij} - (\text{CRPIX1} - 1)\bigr)^2 + \bigl(y_{ij} - (\text{CRPIX2} - 1)\bigr)^2}$$

```python
rsun_pix = hdr["RSUN_OBS"] / abs(hdr["CDELT1"])
disk = r <= rsun_pix
```
Радиус диска в пикселях (размерностный разбор — [[Разбор step1_inspect.py]] §6, п. 2); $R_{\mathrm{pix}} \approx 495.7$ в январе. **Здесь диск полный** ($r \le R_{\mathrm{pix}}$, без обрезки 0.99): цель раздела — посчитать все пятна года, включая лимбовые, тогда как генератор масок режет лимб из-за форшортенинга ([[Генератор масок]] §2). Это третье отличие разведки от v0.2 (после порогов и морфочистки).

```python
spot = (dat < T_SPOT) & disk
n_spot = int(spot.sum())
n_umb = int(((dat < T_UMBRA) & disk).sum())
```
- Скобки в `(dat < T_SPOT) & disk` **обязательны**: побитовый `&` в Python имеет более высокий приоритет, чем сравнение `<`, поэтому без скобок выражение `dat < T_SPOT & disk` распарсилось бы как `dat < (T_SPOT & disk)` — сравнение скаляра с массивом, TypeError или молчаливая чушь. Это главная ловушка булевой логики numpy.
- `spot` — булева маска 1024×1024: True на пикселях, тёмнее 0.90 и внутри диска.
- `spot.sum()` — сумма по булеву массиву = число True (numpy трактует True=1, False=0); `int(...)` приводит `numpy.int64` к `int`.
- `n_umb` — число пикселей umbra; двойные скобки `((dat < T_UMBRA) & disk)` — внутренняя группирует сравнение с маской диска, внешняя нужна потому, что `.sum()` вызывается на результате `&`.
- **Вложенность порогов**: $T_{\mathrm{UMBRA}} = 0.50 < T_{\mathrm{SPOT}} = 0.90$, поэтому $\{\text{umbra}\} \subseteq \{\text{spot}\}$, и далее `penumbra = n_spot - n_umb` имеет смысл «всё пятно минус его ядро». Если бы пороги были независимыми (например, umbra считалась по другому признаку), разность теряла бы физический смысл.

Твой вывод (первый кадр, 20050101_000000): в `stats_spots_2005.csv` строка вида `2005-01-01,1,<spots>,<umbra>,<penumbra>`; для иллюстрации связи с манифестом v0.2: там же `n_spot=303, n_umbra=16, n_penumbra=287` (проверка вложенности: $287 = 303 - 16$ ✓), но в разведке числа будут иными по трём причинам из §2.

Контрастный пример (ошибка без скобок): код `dat < T_SPOT & disk` на скалярном `T_SPOT` и массивном `disk` даёт `TypeError: ufunc 'bitwise_and' not supported for the input types` или, при удачном совпадении типов, инвертированную маску — пятна считаются вне диска.

```python
d = parse_date(p)
stats.append({"date": d.date().isoformat(), "month": d.month,
              "spots": n_spot, "umbra": n_umb,
              "penumbra": n_spot - n_umb})
```
`d.date().isoformat()` — дата без времени в виде `YYYY-MM-DD` (стандарт ISO 8601, сортируется лексикографически = хронологически); `d.month` — целый месяц 1…12; словарь строки накапливается в списке `stats` — потом из него пишется csv и строятся массивы.

```python
if n_spot:
    hist_vals.append(dat[spot][::4])
```
- `if n_spot:` — правда при ненулевом числе пятен (пустой кадр не добавляет ничего в гистограмму).
- `dat[spot]` — булева индексация: одномерный массив интенсивностей **только пикселей пятен** (не всего диска!); это ключевой момент для панели 4: гистограмма строится по распределению $I$ внутри пятен, чтобы искать в нём бимодальность umbra/penumbra.
- `[::4]` — подвыборка каждого 4-го: экономия RAM и времени `np.histogram` при 5139 кадрах (пятен за год — десятки миллионов пикселей, полная гистограмма по всем была бы тяжела).

Твой вывод: `hist_vals` — список из ~4759 подмассивов (по числу кадров с пятнами), суммарно миллионы значений; после `np.concatenate` — один плоский массив для панели 4.

Контрастный пример (год без пятен, гипотетический минимум цикла): `hist_vals` остался бы пуст, и строка `hv = np.concatenate(hist_vals) if hist_vals else np.array([np.nan])` вернула бы `[nan]`, чтобы `np.histogram` не упал на пустом входе, а панель 4 осталась пустой — защита от вырожденного случая.

## 6. Четыре панели `stats_spots_2005.png` и как их читать

```python
dates = [datetime.fromisoformat(s["date"]) for s in stats]
hv = np.concatenate(hist_vals) if hist_vals else np.array([np.nan])
fig, axes = plt.subplots(2, 2, figsize=(12, 9))
```
`subplots(2, 2)` — сетка 2×2 осей; `axes[i, j]` — доступ по индексу; `figsize=(12, 9)` — дюймы.

- **Панель [0,0] — гистограмма размеров пятен** (`hist(spots[spots > 0], bins=50)`): распределение числа пикселей пятна по кадрам с пятнами; длинный правый хвост = редкие гигантские группы (январь), основная масса — малые/средние; читает асимметрию «много мелких, мало крупных».
- **Панель [0,1] — временной ряд активности** (`plot(dates, spots, ".")`): каждый кадр точка; видны «гребёнки» периода ~10–14 суток (солнечная ротация, §6.3), январский и майско-июльский горбы, октябрьская впадина; по оси X — даты (matplotlib парсит `datetime` автоматически).
- **Панель [1,0] — столбцы по месяцам** (`bar(range(1,13), by_month)`): сезонность года одним взглядом; октябрьский столбец почти нулевой — визуальное подтверждение тихого месяца для стратификации сплитов (§6.4).
- **Панель [1,1] — гистограмма $I$ пикселей пятен** (`hist(hv, bins=80, color="tab:red")` + два `axvline`): распределение нормированной интенсивности **внутри пятен** (не диска!); две вертикальные пунктирные линии — текущие разведочные пороги $T_{\mathrm{UMBRA}}=0.50$ (чёрная) и $T_{\mathrm{SPOT}}=0.90$ (синяя). Главный вывод панели: **бимодальности umbra/penumbra нет** — распределение внутри пятен непрерывно спадает от 0.9 к 0.3 без второго горба, поэтому $T_{\mathrm{UMBRA}}$ нельзя выбрать «по долине между двумя пиками», это конвенция, калибруемая по SDD на шаге 3 (§6.4 основной заметки).

Твой вывод (панель 1,1): один пик около 0.85–0.90 (граница penumbra/QS) и монотонный спад влево; линия 0.50 режет хвост без естественной границы.

Контрастный пример (идеализированный случай): если бы фотосферные модели давали чёткие два класса, панель показала бы два горба (около 0.45 и 0.80) с долиной — тогда $T_{\mathrm{UMBRA}}$ ставился бы по минимуму в долине, и калибровка по SDD не требовалась бы; реальность оказалась сложнее, что и зафиксировано в §6.4.

```

    w.writerows(stats)
```
- `newline=""` — обязательный параметр для csv на Windows: без него писатель добавит лишние `\r`, и файл будет двоиться пустыми строками.
- `DictWriter(fieldnames=...)` — колонки фиксированы; `writeheader()` пишет шапку; `writerows(stats)` — все накопленные словари разом.
- Результат — покадровая таблица, из которой шаг 3 (`sdd_validate.py`) и шаг 5 (`select_manual_candidates.py`) берут `n_spot`/`n_umbra` для матчинга и отбора кандидатов; колонка `penumbra` — производная ($n_{\mathrm{spot}} - n_{\mathrm{umbra}}$, вложенность порогов из §4).
