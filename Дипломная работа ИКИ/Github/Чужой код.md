# Краткая справка: использование чужого кода из ZIP

> [!summary] Главное правило
> Если я использую чужой код из ZIP-архива, я сохраняю источник, автора, лицензию и copyright.  
> Если использую только лично — достаточно аккуратной заметки.  
> Если публикую результат — нужно оставить оригинальную лицензию и авторство.

---

## Быстрый алгоритм

- [ ] 1. Проверить лицензию оригинального репозитория.
- [ ] 2. Найти в ZIP файл `LICENSE`, `LICENSE.txt`, `LICENSE.md` или похожий.
- [ ] 3. Не удалять лицензию и copyright-уведомления.
- [ ] 4. Положить рядом заметку `SOURCE.md` или `README.md`.
- [ ] 5. Если буду изменять код — отметить, что код изменён.
- [ ] 6. Если буду публиковать — сохранить оригинальную лицензию и ссылку.

---

## Структура папки

Пример удобной структуры:

```text
my-vault/
  code/
    project-name/
      LICENSE-original.txt
      SOURCE.md
      original/
      modified/
      notes/
```

Если не хочу разделять папки, можно хранить всё вместе, но обязательно оставить:

```text
LICENSE-original.txt
SOURCE.md
```

## Шаблон SOURCE.md

```md
# Source information

## Original project
- Project name: 
- Author: 
- Repository URL: 
- Download method: ZIP archive
- Download date: 
- License: 
- Copyright notice: 

## Status
- Original code included: yes
- Modified: no / yes
- My changes: 

## Notes
- Used for personal study / adaptation / commentary.
- Original code remains copyrighted by its original author.
```

Пример заполнения:

```md
# Source information

## Original project
- Project name: unet
- Author: zhixuhao
- Repository URL: https://github.com/zhixuhao/unet
- Download method: ZIP archive
- Download date: 2026-06-22
- License: MIT License
- Copyright notice: Copyright (c) 2019 zhixuhao

## Status
- Original code included: yes
- Modified: yes
- My changes: added comments, reorganized files, adapted for personal workflow.

## Notes
- Used for personal study and adaptation.
- Original code remains copyrighted by its original author.
```

## Если лицензия MIT

MIT разрешает:

- использовать код;
- копировать;
- изменять;
- дополнять;
- публиковать;
- использовать в своих проектах.

Главное требование:

> Нужно сохранить оригинальный copyright и текст лицензии.

Пример:

```text
Copyright (c) 2019 zhixuhao
```

плюс текст MIT License.

## Минимальный текст для README при публикации

Если когда-нибудь буду публиковать изменённый код:

```md
This project contains code originally written by zhixuhao.

Original project: https://github.com/zhixuhao/unet

Copyright (c) 2019 zhixuhao
License: MIT License

The code has been modified for personal use and study.
```

Или по-русски:

```md
Этот проект содержит код, изначально написанный zhixuhao.

Оригинальный проект: https://github.com/zhixuhao/unet

Copyright (c) 2019 zhixuhao
Лицензия: MIT License

Код был изменён и адаптирован под личные задачи и изучение.
```

## Важные случаи

> [!warning] Если лицензии нет
> Если в репозитории или ZIP нет лицензии, лучше не публиковать такой код у себя без разрешения автора.  
> Для личного изучения можно оставить локально, но публичное распространение может быть рискованным.

> [!info] Если лицензия GPL / AGPL
> Можно изучать и менять, но при публичном распространении изменённого кода обычно нужно сохранять ту же лицензию и открывать исходники.

> [!tip] Если использую только идею, а не код
> Если я не копирую код, а только описываю идею своими словами, лицензия обычно не требуется.  
> Но ссылка на оригинал всё равно хороший тон.

Для личного использования:

```text

```

Для публичного использования:

```text
LICENSE-original.txt
README.md
SOURCE.md
```

## Короткая памятка

> [!check] Всегда делать
> - Сохранять оригинальный `LICENSE`, если он есть.
> - Указывать автора и ссылку.
> - Отмечать, если код был изменён.
> - Хранить дату скачивания.

> [!error] Не делать
> - Не удалять copyright.
> - Не выдавать чужой код за свой.
> - Не публиковать код без лицензии без разрешения.
> - Не утверждать, что оригинальный автор поддерживает мой проект.

---

## Дисклеймер

Это практическая заметка, а не юридическая консультация. Для важных коммерческих или публичных проектов лучше отдельно проверить лицензию и условия использования.
