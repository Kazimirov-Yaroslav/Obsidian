## 1. Формализация задачи

Любая ML-задача начинается с ответа на вопросы:

> [!tip] Чек-лист формализации
> - Что является входом? (данные)
> - Что является выходом? (целевая переменная)
> - Какая ошибка измерима? (метрики)
> - Какой базлайн надо побить? (простые методы)
> - Где модель имеет право ошибаться, а где ошибка физически недопустима?

### Общая постановка

Мы ищем отображение:

$$
f_\theta: X \to Y
$$

где:
- $X$ — входное пространство (изображения Солнца)
- $Y$ — целевое пространство (магнитограммы, маски пятен)
- $\theta$ — параметры модели (веса нейросети)

Обучение — это подбор $\theta$ так, чтобы минимизировать функцию потерь:

$$
\theta^* = \arg\min_\theta \mathbb{E}_{(x,y) \sim \mathcal{D}} [L(f_\theta(x), y)]
$$

где $\mathcal{D}$ — распределение данных, $L$ — функция потерь.

## 2. Входное пространство X

### 2.1. Изображения Солнца в видимом свете

Входные данные — это изображения Солнца, полученные телескопами в континууме (обычно ~6173 Å, линия Fe I).

**Характеристики:**
- 2D-изображение солнечного диска
- Один канал интенсивности (grayscale)
- Разрешение: от 512×512 до 4K+ пикселей
- Динамический диапазон: 8–16 бит
- Геометрия: проекция сферы на плоскость

**Физический смысл:**
- Яркость соответствует температуре фотосферы
- Солнечные пятна — темные области (холоднее на ~1500 K)
- Грануляция — мелкомасштабная текстура
- Потемнение к лимбу — падение яркости к краю диска

### 2.2. Дополнительные признаки (опционально)

Можно добавить координатные каналы:

```python
# Пример: 4-канальный вход
input_tensor = [
    intensity_image,      # исходное изображение
    x_coord,              # x-координата от центра
    y_coord,              # y-координата от центра
    disk_mask             # бинарная маска диска
]
```

### 2.3. Метаданные

Каждое изображение сопровождается метаданными:
- Дата и время наблюдения
- Инструмент (SDO/HMI, GONG, наземный телескоп)
- Координаты центра диска
- Радиус диска в пикселях
- Качество наблюдения (seeing, облачность)

## 3. Целевое пространство Y

### 3.1. Задача 1: Сегментация солнечных пятен

**Выход:** бинарная или многоклассовая маска

**Варианты:**

1. **Бинарная сегментация**
   - 0 = фон
   - 1 = пятно (умбра + пенумбра)

2. **Многоклассовая сегментация**
   - 0 = фон
   - 1 = умбра (темная центральная часть)
   - 2 = пенумбра (светлая периферия)
   - 3 = активная область без пятна (опционально)

**Форма тензора:**
```python
mask.shape = (H, W)        # бинарная
mask.shape = (H, W, C)     # многоклассовая (one-hot)
```

### 3.2. Задача 2: Восстановление магнитного поля

**Выход:** магнитограмма — карта продольной компоненты магнитного поля $B_{LOS}$

**Характеристики:**
- Знаковое поле: положительные и отрицательные значения
- Единицы измерения: Гауссы (G)
- Типичный диапазон: от -3000 G до +3000 G
- Физический смысл: проекция вектора магнитного поля на луч зрения

**Форма тензора:**
```python
magnetogram.shape = (H, W)
# значения в диапазоне [-B_max, +B_max]
```

### 3.3. Скалярные величины (опционально)

Можно также предсказывать:
- Полный магнитный поток: $\Phi = \sum_{i,j} |B_{ij}|$
- Знак доминирующей полярности
- Площадь пятна в квадратных градусах

## 4. Отображение f_θ: X → Y

### 4.1. Модель как функция

Нейросеть — это параметризованная функция:

$$
\hat{y} = f_\theta(x)
$$

где:
- $x$ — входное изображение
- $\hat{y}$ — предсказание (маска или магнитограмма)
- $\theta$ — веса сети (миллионы параметров)

### 4.2. Архитектурные варианты

**Для сегментации:**
- U-Net (encoder-decoder со skip-connections)
- SegNet
- DeepLab

**Для регрессии магнитограмм:**
- U-Net (encoder-decoder для image-to-image)
- ResNet + upsampling
- Autoencoder

**Для мультизадачности:**
- Общий encoder + несколько decoder'ов
- Один вход → несколько выходов

## 5. Функция потерь L(y, ŷ)

Функция потерь измеряет, насколько предсказание $\hat{y}$ отличается от истинного значения $y$.

### 5.1. Для сегментации

**Проблема:** класс "пятно" занимает малую долю пикселей (дисбаланс классов)

**Подходящие лоссы:**

1. **Dice Loss** — региональная метрика, устойчива к дисбалансу
$$
\text{Dice} = \frac{2 \sum_i p_i g_i}{\sum_i p_i + \sum_i g_i}
$$

2. **Focal Loss** — фокусируется на сложных примерах
$$
FL(p_t) = -\alpha_t (1 - p_t)^\gamma \log(p_t)
$$

3. **Tversky Loss** — обобщение Dice с весами для FN/FP

4. **BCE + Dice** — комбинация пиксельного и регионального лоссов

### 5.2. Для магнитограмм

**Проблема:** MSE может быть плох из-за знаков полярности

**Пример плохой ситуации:**
```python
true = [+1000, -1000]  # две противоположные полярности
pred = [0, 0]           # модель предсказала ноль
MSE = 1000000           # большая ошибка
# но физически полярности уничтожены!
```

**Подходящие лоссы:**

1. **L1 Loss (MAE)** — менее чувствителен к выбросам, чем MSE
$$
L_1 = \frac{1}{N} \sum_i |y_i - \hat{y}_i|
$$

2. **Charbonnier Loss** — гладкая версия L1
$$
L_c = \sum_i \sqrt{(y_i - \hat{y}_i)^2 + \epsilon^2}
$$

3. **Знаково-взвешенный лосс**
$$
L_{sign} = \sum_i w(y_i) \cdot |y_i - \hat{y}_i|
$$
где $w(y_i)$ больше для сильных полей

4. **Physics-informed losses**
   - Ошибка суммарного потока: $L_\Phi = |\sum B_{pred} - \sum B_{true}|$
   - Баланс полярностей: $L_{balance} = |\sum B^+_{pred} - \sum B^-_{pred}|$
   - Сохранение границ: $L_{edge} = ||\nabla B_{pred}| - |\nabla B_{true}||$

### 5.3. Комбинированные лоссы

Для мультизадачности:

$$
L_{total} = \lambda_1 L_{segmentation} + \lambda_2 L_{magnetogram} + \lambda_3 L_{physics}
$$

Веса $\lambda_i$ подбираются экспериментально.

## 6. Обучающая, валидационная и тестовая выборки

### 6.1. Разделение данных

**Train set** — для обучения модели
**Validation set** — для подбора гиперпараметров и ранней остановки
**Test set** — для финальной оценки (используется один раз!)

### 6.2. Критически важно: утечки данных

> [!danger] Опасность утечек
> Если модель видит одни и те же данные в train и test, она может "запомнить" их вместо обучения общим закономерностям.

**Типичные утечки в солнечной задаче:**

1. **Временная утечка**
   - Один активный регион в соседние дни попадает в train и test
   - Модель запоминает конкретный регион, а не физику

2. **Пространственная утечка**
   - Один участок диска попадает в соседние патчи train и val
   - Модель интерполирует вместо экстраполяции

3. **Утечка через аугментации**
   - Одно изображение с разными аугментациями в train и test

### 6.3. Правильное разделение

**Вариант 1: По времени**
```python
train: январь-июнь 2023
val: июль-август 2023
test: сентябрь-декабрь 2023
```

**Вариант 2: По Carrington rotations**
```python
train: CR 2200-2210
val: CR 2211-2212
test: CR 2213-2215
```

**Вариант 3: По активным регионам**
```python
# Разделяем по NOAA номерам активных регионов
train_regions = [13000, 13001, ...]
test_regions = [13100, 13101, ...]  # другие регионы
```

## 7. Базлайны

Базлайн — простой метод, который нужно побить, чтобы доказать ценность сложной модели.

### 7.1. Для сегментации

**Naive baseline:**
- Предсказывать все нули (фон)
- Accuracy будет высокой (~99%), но это бесполезно

**Threshold baseline:**
- Пороговая сегментация по интенсивности:
```python
mask = (image < threshold).astype(int)
```

**Classical CV:**
- Морфологические операции
- Детекция темных областей
- Watershed segmentation

### 7.2. Для магнитограмм

**Zero baseline:**
- Предсказывать нулевую магнитограмму
- MAE = среднее значение $|B|$

**Constant baseline:**
- Предсказывать среднее/медианное значение

**Linear baseline:**
- Линейная регрессия: интенсивность → магнитное поле
```python
B_pred = a * intensity + b
```

**Empirical relation:**
- Использовать известные эмпирические соотношения:
  - Площадь пятна → магнитный поток
  - Контраст умбры → сила поля

### 7.3. Зачем нужны базлайны?

> [!tip] Философия базлайнов
> Если сложная нейросеть не бьет простой базлайн — проблема не в архитектуре, а в:
> - Данных (утечки, шум, плохая разметка)
> - Метриках (неправильный выбор)
> - Обучении (плохие гиперпараметры)
> - Постановке задачи (невозможно решить в принципе)

## 8. Декомпозиция задачи

Большую научную задачу лучше разбивать на подзадачи.

### 8.1. Пайплайн решения

```text
Шаг 1: Сегментация солнечных пятен
    ↓
Шаг 2: Выделение активных областей
    ↓
Шаг 3: Предсказание магнитограммы
    ↓
Шаг 4: Оценка полярности и потока
    ↓
Шаг 5: Оценка неопределенности
```

### 8.2. Мультизадачная модель

Одна модель, несколько выходов:

```python
class MultiTaskModel(nn.Module):
    def __init__(self):
        self.encoder = Encoder()
        self.segmentation_head = SegmentationDecoder()
        self.magnetogram_head = MagnetogramDecoder()
        self.polarity_head = PolarityHead()
        
    def forward(self, x):
        features = self.encoder(x)
        return {
            'segmentation': self.segmentation_head(features),
            'magnetogram': self.magnetogram_head(features),
            'polarity': self.polarity_head(features)
        }
```

**Преимущества:**
- Общая feature extraction
- Вспомогательные задачи помогают основной
- Эффективнее по памяти и времени

### 8.3. Каскадная модель

Последовательность моделей:

```python
# Модель 1: сегментация
mask = segmentation_model(image)

# Модель 2: регрессия с учетом маски
magnetogram = magnetogram_model(image, mask)
```

**Преимущества:**
- Можно обучать отдельно
- Легче отлаживать
- Можно использовать разные архитектуры

## 9. Ограничения и физическая корректность

### 9.1. Фундаментальное ограничение

> [!warning] Важно понимать
> Видимое изображение Солнца **не однозначно определяет** магнитное поле.

**Причины:**

1. **Разная физическая природа**
   - Видимый свет — это температура и непрозрачность
   - Магнитное поле — это эффект Зеемана в спектральных линиях

2. **Скрытые структуры**
   - Магнитные поля могут существовать без яркого проявления
   - Тихое Солнце содержит слабые поля, невидимые в континууме

3. **Проекционные эффекты**
   - У лимба одна и та же структура выглядит по-разному
   - Продольная компонента $B_{LOS}$ зависит от угла наблюдения

### 9.2. Что это значит для диплома?

**Честная формулировка:**
- Модель не "восстанавливает" магнитное поле в строгом смысле
- Модель **предсказывает наиболее вероятную** магнитограмму по видимому изображению
- Модель работает хорошо на **активных областях** с сильными полями
- Модель может плохо работать на **тихом Солнце** и у **лимба**

**Обязательные ограничения в работе:**
- Указать, что задача потенциально ill-posed
- Показать, где модель работает хорошо, а где плохо
- Оценить неопределенность предсказаний
- Не утверждать полное восстановление поля

### 9.3. Проверка физической корректности

Метрики должны проверять не только пиксельную точность, но и физику:

```python
# Плохо: только пиксельные метрики
metrics = {
    'MAE': mean_absolute_error(y_true, y_pred),
    'MSE': mean_squared_error(y_true, y_pred)
}

# Хорошо: добавить физические метрики
metrics = {
    'MAE': mean_absolute_error(y_true, y_pred),
    'flux_error': abs(sum(y_pred) - sum(y_true)),
    'polarity_error': check_polarity_consistency(y_pred, y_true),
    'correlation': pearson_correlation(y_true, y_pred),
    'active_region_metrics': compute_metrics_for_AR(y_pred, y_true)
}
```
